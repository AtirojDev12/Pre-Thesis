# Item drop impact

Run `./Tests/ItemImpact/Run-ItemImpactChecks.ps1`. This copies the project to `.utmp/item-impact/Project` and runs Unity 6000.5.7f1 with rendering enabled. Pass `-UnityPath` to select a different Unity executable.

The checks render the real gameplay effect at 0, .055, .12, .18, .27, .35 and .5 seconds and verify layer cutoff, the visible extended smoke tail, shader compilation and surface orientation. They assert vertical volume depth and render the smoke from low front, side and above views at .18 s. They then enter Play mode to drop the actual world flashlight, confirm a centred effect on the supporting surface, check cleanup and suppression while resting, repeat with a 2.5x larger item to verify automatic scaling, and drop onto Unity's Water layer with no effect. A real Mirror host then repeats the collision and checks that its client RPC displays the effect once. Frames and results are written inside the isolated project. The authoring and verification entry points never run automatically on asset import.

For visual review, open either `Assets/VFX/VFX_Preview.unity` or `Assets/VFX/GhostManifestation/VFX_Preview.unity`, press Play, and select **Item drop (0.5 sec)**. Replay a physical drop, toggle **Large item**, then inspect the short streaks, broken ring and longer dust tail using the exact-time slider. Keep the item visible against several dry floor materials and check that no decal or glow remains. The inspection sliders control strength, size and dust; physical drop settings live on `WorldInventoryItem`.

For a two-machine match, drop/throw from both host and remote player. Confirm both machines see the impact at the same contact, the host sees a single effect, lighter bounces are weaker, and resting items never keep emitting. The authoritative impact RPC is reliable and observer-scoped; the visual is local and does not need a network prefab registration. Separate-machine latency and EOS transport still require this manual check.
